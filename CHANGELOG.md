# Журнал изменений Yahont CE

Здесь перечислены отличия Yahont CE от Onyx. Новые записи добавляются сверху.
Выпуски называются `vX.Y.Z`.

## v0.1.1

Исправления и чистка интерфейса после первого выпуска.

Основа: Onyx до коммита [28c31f1039](https://github.com/onyx-dot-app/onyx/commit/28c31f10396bb4127b4bc0c1bfcb0293b907a9fc).

### Исправления

- Уведомления: в колокольчике больше нет сообщений о выпусках Onyx вида «Onyx v4.9.0 is available!» и сообщения «Permissions are changing in Onyx». Сервер больше не скачивает журнал изменений Onyx с GitHub. Уведомления, которые накопились в `v0.1.0`, скрыты и не показываются в списке и в счётчике.
- Панель администратора: убран пункт «Повысить тариф» из боковой панели. Он вёл на страницу, которая в Yahont CE не работает.
- Фоновый воркер в установках без песочниц больше не пишет в лог ошибку `Failed to load Kubernetes configuration` каждую минуту.
- Подвал интерфейса показывает версию выпуска («Yahont v0.1.1») вместо «Yahont 0.0.0-dev». Версия записывается в образы и в сборку из исходников.

### Изменения

- «Настройки индекса», вкладка Self-hosted: скрыты английские модели эмбеддингов `nomic-ai/nomic-embed-text-v1`, `intfloat/e5-base-v2` и `intfloat/e5-small-v2`. Остались многоязычные `intfloat/multilingual-e5-small` (по умолчанию, входит в образ) и `intfloat/multilingual-e5-base` (скачивается с Hugging Face при первом выборе). Модель, которая уже выбрана в вашей установке, остаётся доступной как текущая.

### Прочее

- README: демонстрационное видео, раздел «Коннекторы только читают данные» после списка источников знаний, новая строка в таблице «Для чего это нужно» («Шаблоны договоров, КП и презентаций»), число источников указано как «Более 30».
- В шапке установщиков `install_yahont.sh` и `install_yahont.ps1` сказано, что образы скачиваются из Docker Hub. Поведение установщиков не изменилось.

## v0.1.0

Первый выпуск.

Основа: Onyx до коммита [28c31f1039](https://github.com/onyx-dot-app/onyx/commit/28c31f10396bb4127b4bc0c1bfcb0293b907a9fc).

### Русский язык и бренд

- Русский интерфейс по умолчанию. Каталог переводов переведён полностью.
- Шрифты с кириллицей для интерфейса, текста чатов и кода.
- Название и логотип Yahont вместо Onyx. Ссылки и почта ведут на yahont.ai.
- Атрибуция Onyx сохранена: «Powered by Onyx» в подвале, Onyx Web Crawler.
- Инструмент «Агент кодирования» называется «Агент по коду» (русский интерфейс), задача «Задача кодирования» — «Задача».

### Поиск и индексация

- Модель эмбеддингов по умолчанию: `intfloat/multilingual-e5-small`. Это мультиязычная модель с вектором 384 вместо 768. Раньше стояла `nomic-embed-text-v1`, обученная на английском и слабо работающая с кириллицей. Веса модели лежат в образе `model_server`. Префиксы запроса и документа настроены под эту модель.
- Описание изображений при индексации: промпты по умолчанию просят извлекать текст, числа, даты, суммы, таблицы и вывод терминала дословно, а не пересказывать.
- Баннер на странице «Языковые модели»: показывается, если извлечение изображений включено, а модель для их описания не выбрана.

### Коннекторы

- «S3 (совместимые хранилища)»: Yandex Object Storage, VK Cloud, Selectel, Cloud.ru, Timeweb Cloud, MinIO и другие хранилища с S3 API. Проверен на Timeweb Cloud и SeaweedFS. Адреса и способ адресации остальных провайдеров взяты из их документации. Файлы больше 20 МБ пропускаются.
- «Яндекс Почта» и «Mail.ru» (по IMAP). Вложения писем пока не индексируются, только тело письма.
- IMAP для русской почты:
  - заголовки и названия папок на кириллице;
  - пропуск папок «Спам» и «Корзина»;
  - письма за текущий день;
  - повторное подключение при обрыве;
  - закрытие сессий;
  - письмо индексируется как тред Gmail: даты, отправитель, получатели, папка.
- Каталог «Добавить коннектор» не показывает 24 источника, которые недоступны из России или мало распространены в ней: Linear, Document360, Gong, HubSpot, ClickUp, Asana, Airtable, Salesforce, Zendesk, Axero, Guru, Loopio, LumApps, Slab, Drupal Wiki, Egnyte, Box, OCI Storage, R2, Coda, Productboard, Fireflies, Highspot, Canvas. Список задан в `HIDDEN_CONNECTOR_SOURCES` (`web/src/lib/languageModels/cloudVisibility.ts`). Страница коннектора открывается по прямому адресу `/admin/connectors/<источник>`, созданные коннекторы работают.
- Раздел «ИИ и наблюдаемость» (Braintrust) в каталоге показан: `env.template` задаёт `SHOW_EXTRA_CONNECTORS=true`.

### Модели и сервисы

- RouterAI и Polza.ai (OpenAI-совместимые шлюзы) в разделе «Шлюзы и роутеры»: языковые модели, распознавание и синтез речи, генерация и правка изображений. На карточках есть подпись «Работает в РФ без VPN». Для изображений через эти шлюзы доступны GPT Image 2.5 (Sunburst, Flare): модели Google отказывали даже на нейтральные запросы.
- Веб-поиск через srezai.ru: поиск и чтение страниц.
- Страница «Интеграция Telegram» заменила «Интеграцию Slack» в меню. Сейчас это заглушка с пометкой «в разработке». Уже созданные Slack-боты остаются в таблице, их можно настроить или удалить.

### Развёртывание

- Контейнеры и тома называются по проекту `yahont` (`yahont-api_server-1`, `yahont_db_volume`), а не `onyx`. Образы CE называются `yahontai/yahont-ce-backend`, `yahontai/yahont-ce-web` и `yahontai/yahont-ce-model-server`: это те же имена, что у репозиториев в Docker Hub. Сервисы, которые CE только скачивает (выполнение кода, SeaweedFS), остаются с прежними образами.
- Файлы хранит встроенное объектное хранилище SeaweedFS (сервис `object-store`, профиль `s3-filestore`). Сервисы `minio` и `object-store-copy` убраны из `docker-compose.yml` и `docker-compose.lite.yml`: Onyx использует их только при обновлении прежних установок, а у CE прежних выпусков нет. Из `env.template` убраны переменные `MINIO_ROOT_USER`, `MINIO_ROOT_PASSWORD`, `MINIO_REPLICAS`, `S3_LEGACY_*` и `LEGACY_COPY_*`, а также `ENCRYPTION_KEY_SECRET`: версия MIT не шифрует учётные данные коннекторов, а при заданном значении только пишет предупреждение в лог. Значение `S3_ENDPOINT_URL` по умолчанию теперь `http://object-store:8333`.
- Установщик `deployment/docker_compose/install_yahont.sh` для Linux и macOS (запуск: `curl -fsSL https://yahont.ai/install_yahont.sh | bash`, режим «Лайт»: `... | bash -s -- --lite`) и `install_yahont.ps1` для Windows (запуск в PowerShell: `irm https://yahont.ai/install_yahont.ps1 | iex`, режим «Лайт»: `& ([scriptblock]::Create((irm https://yahont.ai/install_yahont.ps1))) -Lite`): скачивают репозиторий, создают `.env` с секретом входа и запускают Yahont. Установщики проверяют, что порты 80 и 3000 свободны, и останавливаются с понятным сообщением вместо падения `nginx`. Параметр `--bind-local ПОРТ` (`-BindLocal`) создаёт `docker-compose.override.yml` и привязывает Yahont к `127.0.0.1:ПОРТ` для сервера с обратным прокси. Параметр `--project ИМЯ` (`-Project`) задаёт имя проекта Docker Compose, чтобы держать стандартный режим и лайт рядом. После `--no-start` установщик пишет, что запуск не выполнен и какой командой его сделать.
- README, раздел «Быстрый старт»: описаны команды установщика для Linux, macOS и Windows, параметры (`--lite`, `--dir`, `--ref`, `--no-start`) и ссылки на скрипты. Добавлено пояснение, какой адрес открывать, если Yahont запущен на удалённом сервере.
- Режим «Лайт» (`deployment/docker_compose/docker-compose.lite.yml`): работают только PostgreSQL, API, веб, `nginx` и сервис выполнения кода. OpenSearch, Redis, серверы моделей и фоновые воркеры не запускаются. В базовом режиме он использует меньше 1 ГБ памяти. Минимальные и рекомендуемые ресурсы для обоих режимов указаны в README, раздел «Режимы развёртывания». Коннекторы, поиск по документам и знания агентов в лайте отключены. Запуск описан в README, раздел «Режимы развёртывания».
- Инструкция `docs/reverse-proxy.md`: Nginx и Let's Encrypt перед Yahont, привязка порта к `127.0.0.1`, WebSocket, автопродление сертификата.
- Предупреждение в README: Docker Compose публикует порты 80 и 3000 на всех сетевых интерфейсах. Там же пример файла `docker-compose.override.yml` для привязки к `127.0.0.1`.
- `deployment/docker_compose/env.template` написан на русском. Убраны настройки Onyx Craft, переменные только для Enterprise Edition и подсказки установщика. Добавлены `OPENSEARCH_ADMIN_PASSWORD`, `HOST_PORT`, `BASE_IMAGE_REGISTRY`, `DOCKER_SOCK_PATH`.
- Значение `USER_AUTH_SECRET` в `.env` обязательно: без него `api_server` не запускается. В быстром старте README добавлен шаг, который его создаёт.

### Исправления

- DeepSeek: вызов инструмента в формате DSML больше не показывается пользователю текстом, инструмент вызывается.
- Из заголовка `Permissions-Policy` убраны 7 директив, которые удалены из стандарта W3C. Chrome больше не пишет о них предупреждение на каждой странице.
- Изолированные дочерние процессы получают корень `backend` в `PYTHONPATH`: тесты можно запускать из корня репозитория.
- Страница «Пользователи»: вместо оповещения Onyx о миграции прав («Права изменились») показана подсказка «Права по группам» со ссылкой на документацию.

### Прочее

- Готовые образы `yahontai/yahont-ce-backend`, `yahontai/yahont-ce-web` и `yahontai/yahont-ce-model-server` опубликованы в Docker Hub с тегами выпуска (`vX.Y.Z`) и `latest` для платформы linux/amd64. `docker compose up -d` скачивает их, сборка не нужна. Тег задаёт `IMAGE_TAG` в `.env`. Обновление: `git pull`, `docker compose pull`, `docker compose up -d`. Сборка из исходного кода осталась: `docker compose up -d --build`.
- Установщики (`install_yahont.sh`, `install_yahont.ps1`) скачивают образы командой `docker compose pull` и запускают Yahont без сборки.
- Анонимная телеметрия выключена: шаблон `.env` задаёт `DISABLE_TELEMETRY=true`. Адрес отправки в коде заменён с сервера Onyx на `telemetry.yahont.ai`. При значении `false` Yahont отправляет на этот адрес версию, события регистрации и действий, статусы индексации коннекторов, задержки функций, метрики очередей и идентификатор инстанса. Тексты документов и сообщений не отправляются.
- Встраиваемый виджет чата для сайтов (`widget/`, `examples/widget`) не входит в CE.
- В CE нет серверной части Enterprise Edition (`backend/ee`): функции, которым она нужна, недоступны.
- Папки `web/src/ee` и `web/src/app/ee` совпадают с Onyx без изменений и остаются под лицензией Onyx Enterprise License (см. `LICENSE` в каждой папке).
- README и политика безопасности написаны на русском.
